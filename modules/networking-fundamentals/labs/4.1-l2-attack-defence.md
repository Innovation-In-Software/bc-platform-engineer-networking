# Lab 08 – L2 Attack & Defence Simulation

**Objective:**  
Configure the three core Layer 2 defence mechanisms on a Cisco switch — DHCP Snooping, Dynamic ARP Inspection, and Port Security — and observe how each one protects the network. You will build a small LAN, observe baseline behaviour, then apply defences one at a time and verify each one is working.

> **Packet Tracer limitation:** Packet Tracer cannot send crafted ARP frames from a PC, so you cannot simulate the actual attack traffic. What you *can* do — and what this lab focuses on — is configure and verify the defences that would block those attacks in a real environment. This is the exam-relevant skill.

## Step 3. Configure DHCP Snooping

DHCP Snooping tells the switch to distrust DHCP messages arriving on access ports. Only the trusted uplink (the router port) is allowed to send DHCP Offers and Acknowledgements. This blocks rogue DHCP servers.

### Enable DHCP Snooping on SW0
Click **SW0 → CLI**:

```
SW0(config)# ip dhcp snooping
SW0(config)# ip dhcp snooping vlan 1

SW0(config)# interface FastEthernet0/1
SW0(config-if)# ip dhcp snooping trust
SW0(config-if)# exit
```

> **Why trust only Fa0/1?** Fa0/1 connects to the legitimate router. All PC ports (Fa0/2–5) are untrusted by default — if a PC tries to act as a DHCP server, the switch drops its Offer/Ack messages.

### Force PCs to renew their DHCP leases
Click each PC → **Desktop → IP Configuration** → toggle to **Static** then back to **DHCP**.  
Each PC should receive the same address from the legitimate router.

### Verify the DHCP Snooping binding table
```
SW0# show ip dhcp snooping binding
```

**Expected output:**
```
MacAddress          IpAddress        Lease(sec)  Type           VLAN  Interface
------------------  ---------------  ----------  -------------  ----  ---------------
xxxx.xxxx.xxxx      192.168.10.11    86400       dhcp-snooping  1     FastEthernet0/2
xxxx.xxxx.xxxx      192.168.10.12    86400       dhcp-snooping  1     FastEthernet0/3
xxxx.xxxx.xxxx      192.168.10.13    86400       dhcp-snooping  1     FastEthernet0/4
xxxx.xxxx.xxxx      192.168.10.14    86400       dhcp-snooping  1     FastEthernet0/5
```

> **This binding table is critical.** DAI (next step) uses it to validate ARP messages. Every MAC/IP pair learned through DHCP Snooping becomes a trusted reference.

## Step 4. Configure Dynamic ARP Inspection (DAI)

DAI intercepts all ARP messages on untrusted ports and checks them against the DHCP Snooping binding table. If an ARP message claims an IP/MAC pair that doesn't match a binding entry, the switch drops the frame.

### Enable DAI on SW0
```
SW0(config)# ip arp inspection vlan 1

SW0(config)# interface FastEthernet0/1
SW0(config-if)# ip arp inspection trust
SW0(config-if)# exit
```

> **Why trust Fa0/1?** The router's IP (192.168.10.1) is its own address — it doesn't have a DHCP snooping binding entry. Without marking the router port as trusted, DAI would drop the router's own ARP replies.

### Verify DAI is active
```
SW0# show ip arp inspection vlan 1
```

**Expected output:**
```
Vlan    Forwarded        Dropped     DHCP Drops      ACL Drops
----    ---------        -------     ----------      ---------
   1            0              0              0              0
```

### Generate some ARP traffic and check statistics
Ping between PCs to generate ARP activity:
```
C:\> ping 192.168.10.12
C:\> ping 192.168.10.1
```

Then check:
```
SW0# show ip arp inspection statistics
```

You should see the Forwarded counter incrementing for legitimate ARP traffic.

## Step 5. Configure Port Security

Port Security limits which MAC addresses are allowed on each switch port. If a device with an unknown MAC address connects, the switch takes a configured action — in this lab, it shuts down the port (err-disable).

### Enable Port Security on all PC ports
```
SW0(config)# interface range FastEthernet0/2 - 5
SW0(config-if-range)# switchport port-security
SW0(config-if-range)# switchport port-security maximum 1
SW0(config-if-range)# switchport port-security violation shutdown
SW0(config-if-range)# switchport port-security mac-address sticky
SW0(config-if-range)# exit
```

> **What `sticky` does:** The switch dynamically learns the first MAC it sees on each port and permanently records it. You don't need to manually enter MAC addresses. The sticky MACs are saved to the running config.

### Verify port security is configured
```
SW0# show port-security
```

**Expected output:**
```
Secure Port  MaxSecureAddr  CurrentAddr  SecurityViolation  Security Action
             (Count)        (Count)      (Count)
---------------------------------------------------------------------------
    Fa0/2                1            1                  0          Shutdown
    Fa0/3                1            1                  0          Shutdown
    Fa0/4                1            1                  0          Shutdown
    Fa0/5                1            1                  0          Shutdown
```

```
SW0# show port-security interface FastEthernet0/2
```

**Expected output:**
```
Port Security              : Enabled
Port Status                : Secure-up
Violation Mode             : Shutdown
Aging Time                 : 0 mins
Aging Type                 : Absolute
SecureStatic Address Aging : Disabled
Maximum MAC Addresses      : 1
Total MAC Addresses        : 1
Configured MAC Addresses   : 0
Sticky MAC Addresses       : 1
Last Source Address:Vlan   : xxxx.xxxx.xxxx:1
Security Violation Count   : 0
```

### Simulate a port security violation
1. Note which port PC0 is connected to (Fa0/2)
2. In Packet Tracer, delete the cable between PC0 and SW0 Fa0/2
3. Connect PC1's cable to SW0 Fa0/2 instead (a different MAC address now on that port)
4. Observe the port LED on SW0 turn amber (err-disabled)

Check the port:
```
SW0# show port-security interface FastEthernet0/2
```
You should see: `Port Status: Secure-shutdown` and `Security Violation Count: 1`

### Recover the err-disabled port
```
SW0(config)# interface FastEthernet0/2
SW0(config-if)# shutdown
SW0(config-if)# no shutdown
SW0(config-if)# exit
```

Reconnect the correct PC to Fa0/2 and verify the port comes back up.

## Summary

| Defence | What It Stops | Key Command |
|---------|--------------|-------------|
| DHCP Snooping | Rogue DHCP servers on access ports | `ip dhcp snooping` / `ip dhcp snooping trust` |
| Dynamic ARP Inspection | ARP spoofing / MITM attacks | `ip arp inspection vlan` / `ip arp inspection trust` |
| Port Security | MAC flooding / unauthorised device connections | `switchport port-security` / `mac-address sticky` |
