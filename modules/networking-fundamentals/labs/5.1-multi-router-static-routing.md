# Lab 09 – Multi-Router Static Routing

**Objective:**  
Build a three-router chain and manually configure static routes so that every subnet can reach every other subnet. By the end of the lab every PC can ping every other PC and you can read the routing table to explain exactly why each packet takes the path it does.

---

## Step 3. Configure Static Routes

At this point each router only knows its directly connected subnets. R1 cannot reach 192.168.3.0/24 because it has no route to it. We need to tell each router about every remote subnet and which next-hop to use.

### R1 — needs to reach R2–R3 link and R3 LAN
```
R1(config)# ip route 10.0.23.0 255.255.255.252 10.0.12.2
R1(config)# ip route 192.168.3.0 255.255.255.0 10.0.12.2
```

> **Why both?** R1 needs a route to the R2–R3 transit subnet (10.0.23.0/30) so it can reach R3's interfaces, and a route to R3's LAN (192.168.3.0/24) so PC-A can reach PC-C. Both point to the same next-hop: R2's Gi0/0 address (10.0.12.2).

### R2 — needs to reach both LANs
```
R2(config)# ip route 192.168.1.0 255.255.255.0 10.0.12.1
R2(config)# ip route 192.168.3.0 255.255.255.0 10.0.23.2
```

> R2 is the transit router — it must know how to reach both LANs. Traffic for R1's LAN goes back toward R1 (10.0.12.1), traffic for R3's LAN goes forward toward R3 (10.0.23.2).

### R3 — needs to reach R1–R2 link and R1 LAN
```
R3(config)# ip route 10.0.12.0 255.255.255.252 10.0.23.1
R3(config)# ip route 192.168.1.0 255.255.255.0 10.0.23.1
```

## Step 7. Observe a Route Failure

### Remove one static route from R2
```
R2(config)# no ip route 192.168.1.0 255.255.255.0 10.0.12.1
```

### Test from PC-A
```
C:\> ping 192.168.3.10
```
Pings should now fail — R2 drops packets destined for 192.168.1.0 because it has no route.

### Check what R2 shows
```
R2# show ip route
```
Confirm the 192.168.1.0/24 static route is gone.

### Restore the route
```
R2(config)# ip route 192.168.1.0 255.255.255.0 10.0.12.1
```
Re-run the ping and confirm it succeeds again.

- What happens if R1 has a static route to 192.168.3.0/24 but R3 has no route back to 192.168.1.0/24? Why does routing need to work in both directions?
