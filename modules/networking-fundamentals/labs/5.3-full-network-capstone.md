# Lab 11 – Full Network Capstone

**Objective:**  
Build a complete two-site network from scratch applying every skill from Days 1–5. There are no step-by-step config commands in this lab — you are expected to recall and apply what you have learned. Use your notes and previous labs as a reference.

> This lab is intentionally open-ended. The goal is not just to get pings working — it is to understand why each piece is needed and be able to explain your decisions.

---

## Scenario

You are a network engineer building the infrastructure for a small company with two offices.

**Site A** is the main office. It has two departments on separate VLANs — HR (VLAN 10) and Guest Wi-Fi (VLAN 20). The Guest network must not be able to reach internal servers at Site B. Both departments get IPs from DHCP. The switch must be hardened against Layer 2 attacks.

**Site B** is the data centre. It has a single server subnet. Servers have static IPs.

The two sites are connected via a router-to-router link.

## Requirements Checklist

Work through each requirement in order. Check it off as you complete and verify it.

---

### ☐ 1. Site A Switch — VLANs and Trunking

Configure SW-A with:
- VLAN 10 named HR
- VLAN 20 named GUEST
- VLAN 99 named NATIVE (used as native VLAN on trunk)
- Trunk port to R-A: allowed VLANs 10, 20, 99; native VLAN 99
- Access port for HR PC in VLAN 10
- Access port for Guest PC in VLAN 20

**Verify:**
```
SW-A# show vlan brief
SW-A# show interfaces trunk
```
Confirm VLAN 10 and 20 are active and the trunk shows both in the allowed and forwarding columns.

---

### ☐ 2. Router-on-a-Stick — Inter-VLAN Routing at Site A

Configure sub-interfaces on R-A Gi0/0:
- Gi0/0.10: encapsulation dot1q 10; IP = 192.168.10.1/24
- Gi0/0.20: encapsulation dot1q 20; IP = 192.168.20.1/24
- Gi0/0: bring the physical interface up (no shutdown) — no IP on the parent

**Verify:**
```
R-A# show ip interface brief
```
Both sub-interfaces should show up/up. Ping 192.168.10.1 from R-A — should succeed.

---

### ☐ 3. DHCP — Automatic IP Assignment for Site A

Configure two DHCP pools on R-A:
- Pool HR: network 192.168.10.0/24, default-router 192.168.10.1, exclude .1–.10
- Pool GUEST: network 192.168.20.0/24, default-router 192.168.20.1, exclude .1–.10

Set HR PC and Guest PC to DHCP in Desktop → IP Configuration.

**Verify:**
```
R-A# show ip dhcp pool
R-A# show ip dhcp binding
```
Confirm each PC received an address. Record the IPs they received — you will need them for testing.

| PC | IP Received | Subnet |
|----|-------------|--------|
| HR PC | | 192.168.10.0/24 |
| Guest PC | | 192.168.20.0/24 |

---

### ☐ 4. WAN Link and Site B Configuration

Configure the router-to-router link:
- R-A Gi0/1: 10.0.99.1/30
- R-B Gi0/0: 10.0.99.2/30

Configure Site B:
- R-B Gi0/1: 192.168.30.1/24
- Server: static IP 192.168.30.10/24, gateway 192.168.30.1

**Verify:**
```
R-A# ping 10.0.99.2    ← should succeed
R-B# ping 10.0.99.1    ← should succeed
```

---

### ☐ 5. OSPF — Dynamic Routing Between Sites

Configure OSPF on both routers. Advertise all subnets into area 0.

R-A must advertise: 192.168.10.0/24, 192.168.20.0/24, 10.0.99.0/30  
R-B must advertise: 192.168.30.0/24, 10.0.99.0/30

Apply passive-interface on any interface facing end devices.

**Verify:**
```
R-A# show ip ospf neighbor       ← must show FULL
R-A# show ip route ospf          ← must show O 192.168.30.0/24
R-B# show ip route ospf          ← must show O 192.168.10.0 and 192.168.20.0
```

Before applying the ACL (next step), confirm HR PC can ping the Server:
```
C:\> ping 192.168.30.10    ← from HR PC — should succeed
C:\> ping 192.168.30.10    ← from Guest PC — should also succeed (no ACL yet)
```

---

### ☐ 6. ACL — Block Guest from Site B

Write an extended ACL that:
- Denies traffic from 192.168.20.0/24 to 192.168.30.0/24
- Permits all other traffic

Apply it near the source — inbound on R-A Gi0/0.20.

**Verify:**
```
R-A# show access-lists
```
Confirm the ACL exists and is applied.

```
C:\> ping 192.168.30.10    ← from Guest PC — should now FAIL
C:\> ping 192.168.30.10    ← from HR PC — should still SUCCEED
```

Check match counters on the ACL after testing:
```
R-A# show access-lists
```
The deny rule should show at least one match.

---

### ☐ 7. Layer 2 Security on SW-A

Configure the following on SW-A:

**DHCP Snooping:**
- Enable globally
- Enable on VLAN 10 and VLAN 20
- Mark the trunk port to R-A as trusted
- All PC access ports are untrusted (default)

**Dynamic ARP Inspection:**
- Enable on VLAN 10 and VLAN 20
- Mark the trunk port to R-A as trusted

**Port Security on PC access ports:**
- Maximum 1 MAC address
- Violation action: shutdown
- MAC address: sticky

**Verify:**
```
SW-A# show ip dhcp snooping binding
SW-A# show ip arp inspection vlan 10
SW-A# show port-security
```

> **Important:** After enabling DHCP Snooping, the PCs may need to renew their DHCP leases. Toggle them from DHCP to Static and back to DHCP if they lose their IP.

## Troubleshooting Guide

If something is not working, use this guide before asking for help.

| Symptom | Where to look | Command |
|---------|--------------|---------|
| PC not getting DHCP | DHCP pool, snooping trust, VLAN | show ip dhcp pool / show ip dhcp snooping |
| Inter-VLAN routing not working | Sub-interface encapsulation, trunk | show ip int brief / show interfaces trunk |
| OSPF not forming | Area mismatch, subnet mismatch, passive-interface | show ip ospf neighbor |
| Routes missing | OSPF network statement, wildcard mask | show ip ospf database |
| ACL blocking wrong traffic | Rule order, placement, direction | show access-lists / show ip interface |
| Port security err-disabled | Wrong MAC on port | show port-security interface |

## Reflection

- You applied the ACL inbound on Gi0/0.20. Why inbound rather than outbound? What would change if you applied it outbound on R-B's LAN interface instead?
- DHCP Snooping requires the trunk port to R-A to be trusted. Why? What would happen if you left it untrusted?
- Walk through what happens step by step when the Guest PC sends a packet to the Site B server after the ACL is in place.
- If you added a second access port on SW-A in VLAN 10 and plugged in a new PC — what would happen with port security configured, and what would you need to do?
- OSPF is advertising 192.168.20.0/24 (Guest subnet) to R-B. Is this a security issue? How would you prevent R-B from even knowing the Guest subnet exists?
