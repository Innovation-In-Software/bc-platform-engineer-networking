# Lab 05 – Two Subnets, DHCP & DNS

**Objective:**  
Connect two subnets through a single router. Clients on the LAN get their addresses automatically via DHCP. A server on the second subnet has a static IP and runs DNS. Verify that clients can reach the server by IP address and by hostname.

---

## Topology

```
[PC0] ──┐
[PC1] ──┴── [SW0] ── [Router0] ── [SW1] ── [Server0]
              (LAN)            (Server subnet)
```

### Connection Details
| Cable Type | From | Port | To | Port |
|------------|------|------|----|------|
| Copper Straight-Through | PC0 | FastEthernet0 | SW0 | FastEthernet0/1 |
| Copper Straight-Through | PC1 | FastEthernet0 | SW0 | FastEthernet0/2 |
| Copper Straight-Through | SW0 | FastEthernet0/24 | Router0 | GigabitEthernet0/0 |
| Copper Straight-Through | Router0 | GigabitEthernet0/1 | SW1 | FastEthernet0/1 |
| Copper Straight-Through | Server0 | FastEthernet0 | SW1 | FastEthernet0/2 |

### IP Address Plan
| Device | Interface | IP Address | Subnet Mask |
|--------|-----------|------------|-------------|
| Router0 | Gi0/0 | 192.168.1.1 | 255.255.255.0 |
| Router0 | Gi0/1 | 192.168.2.1 | 255.255.255.0 |
| Server0 | NIC | 192.168.2.10 | 255.255.255.0 |
| PC0 | NIC | DHCP | — |
| PC1 | NIC | DHCP | — |

---

## Step 1. Build the Topology

Place all devices on the canvas and cable them using the Connection Details table above. All cables are **Copper Straight-Through**.

---

## Step 2. Configure Router0

Click **Router0 → CLI**:

```
Router> enable
Router# configure terminal
Router(config)# hostname Router0

Router0(config)# interface GigabitEthernet0/0
Router0(config-if)# ip address 192.168.1.1 255.255.255.0
Router0(config-if)# no shutdown
Router0(config-if)# exit

Router0(config)# interface GigabitEthernet0/1
Router0(config-if)# ip address 192.168.2.1 255.255.255.0
Router0(config-if)# no shutdown
Router0(config-if)# exit
```

Verify both interfaces are up:
```
Router0# show ip interface brief
```
Both Gi0/0 and Gi0/1 should show **up/up**.

---

## Step 3. Configure DHCP on Router0

```
Router0# configure terminal
Router0(config)# ip dhcp excluded-address 192.168.1.1 192.168.1.10

Router0(config)# ip dhcp pool LAN
Router0(dhcp-config)# network 192.168.1.0 255.255.255.0
Router0(dhcp-config)# default-router 192.168.1.1
Router0(dhcp-config)# dns-server 192.168.2.10
Router0(dhcp-config)# exit
```

### Set PCs to use DHCP
Click **PC0 → Desktop → IP Configuration → DHCP**. Repeat for PC1.

Each PC should receive a 192.168.1.x address automatically.

### Verify
```
Router0# show ip dhcp binding
```

| Device | Assigned IP | Gateway | DNS Server |
|--------|-------------|---------|------------|
| PC0 | | | |
| PC1 | | | |

---

## Step 4. Configure Server0

Click **Server0 → Desktop → IP Configuration → Static**:
- IP Address: 192.168.2.10
- Subnet Mask: 255.255.255.0
- Default Gateway: 192.168.2.1

### Enable DNS
Click **Server0 → Services → DNS**:
1. Toggle DNS to **On**
2. Add a record:
   - Name: server.local
   - Type: A Record
   - Address: 192.168.2.10
   - Click **Add**

---

## Step 5. Test Connectivity

### From PC0 Command Prompt — ping by IP
```
C:\> ping 192.168.1.1
C:\> ping 192.168.2.10
```
Both should succeed. The first confirms PC0 can reach its gateway. The second confirms the router is forwarding traffic between the two subnets.

### Ping by hostname
```
C:\> ping server.local
```
This should resolve to 192.168.2.10 and reply successfully.

### Check the ARP cache
```
C:\> arp -a
```
You should see the router's MAC address mapped to 192.168.1.1 — ARP ran automatically when PC0 first sent traffic.

---

## Step 6. Verify

```
Router0# show ip dhcp binding
Router0# show ip route
```

show ip route should show two directly connected routes — one for each subnet.

### Verification Table
| Test | Expected Result | Pass/Fail |
|------|----------------|-----------|
| Gi0/0 up/up | show ip int brief | |
| Gi0/1 up/up | show ip int brief | |
| PC0 got DHCP address | ipconfig on PC0 | |
| PC1 got DHCP address | ipconfig on PC1 | |
| Ping gateway | ping 192.168.1.1 succeeds | |
| Ping server by IP | ping 192.168.2.10 succeeds | |
| Ping server by name | ping server.local succeeds | |
| ARP entry for gateway | arp -a shows 192.168.1.1 | |

## Reflection Questions

1. PC0 is on 192.168.1.0/24 and Server0 is on 192.168.2.0/24. Why can they communicate without any static routes configured?
2. Why does Server0 use a static IP instead of DHCP?
3. What would happen if you forgot to exclude 192.168.1.1 from the DHCP pool?
4. The ARP cache on PC0 shows the router's MAC but not Server0's MAC. Why?

## Summary

| Concept | Description |
|---------|-------------|
| Two subnets | Router connects 192.168.1.0/24 (LAN) and 192.168.2.0/24 (servers) |
| DHCP | PCs receive IP, gateway, and DNS server automatically |
| Static IP | Server always uses a fixed address — clients need to find it reliably |
| DNS | Resolves server.local to 192.168.2.10 |
| ARP | Runs automatically when PC0 first contacts the gateway |
| Inter-subnet routing | Router forwards traffic between subnets using its routing table |
