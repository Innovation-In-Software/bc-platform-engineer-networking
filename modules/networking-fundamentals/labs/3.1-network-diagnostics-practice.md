## Step 2. Ping — Layer by Layer

Ping is not just a connectivity test — used systematically it tells you exactly which OSI layer has a problem. Work through the following tests in order and record your results in the table at the end of this step.

### Test 1: Loopback — confirm the TCP/IP stack is working
Click **PC0** → **Desktop** → **Command Prompt:**
```
C:\> ping 127.0.0.1
```
- **What this tests:** Layer 3–4 stack on the local machine only — no traffic leaves the NIC
- **Expected:** 4 replies from 127.0.0.1

### Test 2: Local gateway — confirm Layer 1/2/3 to the router
```
C:\> ping 192.168.10.1
```
- **What this tests:** Physical cable, switch forwarding, ARP resolution, router LAN interface
- **If this fails:** The problem is at Layer 1 (cable), Layer 2 (switch/VLAN), or Layer 3 (IP config)
- **Expected:** 4 replies from 192.168.10.1

### Test 3: Same-subnet host — confirm Layer 2 switching
```
C:\> ping 192.168.10.11
```
- **What this tests:** Switch MAC learning and forwarding within LAN1
- **Expected:** 4 replies from 192.168.10.11

### Test 4: Remote subnet — confirm inter-subnet routing
```
C:\> ping 192.168.20.10
```
- **What this tests:** Router0 forwarding between G0/0/0 and G0/0/1 (Layer 3 routing)
- **If gateway ping succeeded but this fails:** The problem is in routing, not cabling
- **Expected:** 4 replies from 192.168.20.10

### Test 5: Server — confirm end-to-end within LAN1
```
C:\> ping 192.168.10.100
```
- **Expected:** 4 replies from Server0

### Ping Results Table — fill this in as you test
| Test | Source | Destination | Result | OSI Layer Tested |
|------|--------|-------------|--------|-----------------|
| Loopback | PC0 | 127.0.0.1 | | L3–L4 (local stack) |
| Gateway | PC0 | 192.168.10.1 | | L1–L3 |
| Same subnet | PC0 | 192.168.10.11 | | L2 (switching) |
| Remote subnet | PC0 | 192.168.20.10 | | L3 (routing) |
| Server | PC0 | 192.168.10.100 | | L1–L3 |

> **Interpreting ping output:**
> - `!` = reply received — hop is reachable
> - `.` = timeout — no reply within the window
> - `U` = destination unreachable — a router sent back an ICMP unreachable message
> - `M` = MTU issue — packet too large, fragmentation needed

## Step 4. ARP — Verify Layer 2 Discovery

ARP links Layer 3 (IP addresses) to Layer 2 (MAC addresses). Checking ARP tables confirms that devices have successfully discovered each other at Layer 2.

### Check PC0's ARP cache
Click **PC0** → **Desktop** → **Command Prompt:**
```
C:\> arp -a
```
- **Expected:** An entry for `192.168.10.1` showing Router0's MAC address
- **Why the gateway appears:** PC0 sends all off-subnet traffic to the gateway, so it ARPs for it first

### Check Router0's ARP table
Click **Router0** → **CLI** tab:
```
Router0# show arp
```

**Expected output:**

## Step 6. Show IP Interface Brief

This is the most-used verification command on a Cisco router. It gives a one-line summary of every interface.

### Run on Router0
```
Router0# show ip interface brief
```

**Expected output:**
```
Interface              IP-Address      OK? Method Status                Protocol
GigabitEthernet0/0/0   192.168.10.1    YES manual up                    up
GigabitEthernet0/0/1   192.168.20.1    YES manual up                    up
GigabitEthernet0/0/2   unassigned      YES unset  administratively down down
```

### Interpret the Status and Protocol columns:
| Status / Protocol | Meaning |
|-------------------|---------|
| up / up | Interface is fully operational |
| up / down | Layer 1 is fine but Layer 2 has a problem (encapsulation mismatch) |
| administratively down / down | Interface has been manually shut down with `shutdown` command |
| down / down | Layer 1 failure — cable unplugged, other device is off |

## Step 8. Show Interfaces — Reading Error Counters

`show interfaces` gives full statistics for a single interface including error counters — these reveal physical layer problems.

```
Router0# show interfaces g0/0/0
```

**Key fields to find and record:**
```
GigabitEthernet0/0/0 is up, line protocol is up
  Hardware is ...
  Internet address is 192.168.10.1/24
  MTU 1500 bytes, BW 1000000 Kbit/sec
  ...
  5 minute input rate 0 bits/sec, 0 packets/sec
  5 minute output rate 0 bits/sec, 0 packets/sec
     X packets input, X bytes, 0 no buffer
     0 runts, 0 giants, 0 throttles
     0 input errors, 0 CRC, 0 frame
     X packets output, X bytes, 0 underruns
     0 output errors, 0 collisions
```

### Error Counter Reference:
| Counter | What It Means |
|---------|--------------|
| CRC errors | Frames arriving with corrupted data — usually a bad cable or duplex mismatch |
| Runts | Frames smaller than 64 bytes — often a collision or duplex issue |
| Giants | Frames larger than 1518 bytes — possible MTU misconfiguration |
| Input errors | Total of all inbound frame errors |
| Output drops | Outgoing packets dropped due to queue overflow — possible congestion |

## Step 9. Pipe Modifiers — Filtering Large Outputs

The `|` (pipe) modifier filters the output of any `show` command so you only see what you need.

Run each of the following on **Router0** and record what each returns:

```
Router0# show running-config | include ip address
```
- **What it does:** Shows only lines containing the text "ip address" — useful for quickly finding all configured IPs

```
Router0# show running-config | section interface
```
- **What it does:** Shows each interface block in full

```
Router0# show ip route | include 192.168.20
```
- **What it does:** Filters the routing table to only show entries matching 192.168.20

```
Router0# show interfaces | include errors
```
- **What it does:** Pulls error counter lines from all interfaces at once
