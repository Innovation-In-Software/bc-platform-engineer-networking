# Lab 10 – Standard & Extended ACLs: Multi-Department Access Control

**Objective:**  
Apply standard and extended ACLs to enforce an access control policy across three department subnets. You will experience firsthand why ACL placement matters — a standard ACL placed in the wrong location blocks the wrong traffic — and build toward a policy that allows fine-grained, per-service access control between departments.

## Step 2. Standard ACL — Block Guest from HR

A standard ACL matches only on **source IP address**. It is a blunt instrument — it cannot distinguish which port or protocol is being used, only who is sending the traffic.

### Why use a standard ACL here?
The policy is "Guest cannot access HR — for any reason, on any port." There is no need for granularity, so a standard ACL is appropriate.

### Placement rule for standard ACLs
> Standard ACLs should be placed **as close to the destination as possible** because they can only match source IP. If placed near the source, they would block traffic to ALL destinations, not just the intended one.

In this case, the destination is HR (Gi0/0). We apply the ACL **outbound on Gi0/0**.

### Write and apply Standard ACL 10
```
Router0(config)# access-list 10 remark Block Guest subnet from HR
Router0(config)# access-list 10 deny 10.0.30.0 0.0.0.255

Router0(config)# access-list 10 remark Permit all other traffic
Router0(config)# access-list 10 permit any

Router0(config)# interface GigabitEthernet0/0
Router0(config-if)# ip access-group 10 out
Router0(config-if)# exit
```

> **Why `permit any` at the end?** Without it, the implicit deny at the end of every ACL would block Finance and HR traffic to HR as well — not what we want.

### Test Standard ACL 10
```
# From Guest PC0:
C:\> ping 10.0.10.10    -- should now FAIL (blocked)
C:\> ping 10.0.10.100   -- should now FAIL (blocked)
C:\> ping 10.0.20.10    -- should still SUCCEED (Finance not blocked)

# From Finance PC0:
C:\> ping 10.0.10.10    -- should still SUCCEED (Finance not blocked)
C:\> ping 10.0.10.100   -- should still SUCCEED
```

Check match counters:
```

```

## Step 3. Placement Exercise — What Goes Wrong If You Place It Wrong?

Before continuing, let's prove why standard ACL placement matters.

### Remove ACL 10 from Gi0/0 and apply it to Gi0/2 instead (near the source)
```
Router0(config)# interface GigabitEthernet0/0
Router0(config-if)# no ip access-group 10 out
Router0(config-if)# exit

Router0(config)# interface GigabitEthernet0/2
Router0(config-if)# ip access-group 10 in
Router0(config-if)# exit
```

### Test the wrong placement
```
# From Guest PC0:
C:\> ping 10.0.10.10    -- blocked (good -- this is what we wanted)
C:\> ping 10.0.20.10    -- ALSO BLOCKED (bad -- Guest is blocked from Finance too)
```

> **What happened?** Standard ACL 10 blocks all traffic from the Guest subnet — but when applied inbound on Gi0/2, it blocks Guest traffic going EVERYWHERE, not just to HR. The ACL cannot tell the difference between "going to HR" and "going to Finance" because it only looks at the source IP.

### Restore correct placement
```
Router0(config)# interface GigabitEthernet0/2
Router0(config-if)# no ip access-group 10 in
Router0(config-if)# exit

Router0(config)# interface GigabitEthernet0/0
Router0(config-if)# ip access-group 10 out
Router0(config-if)# exit
```

Verify Guest→HR is blocked, Guest→Finance is permitted again.

## Step 4. Extended ACL — Fine-Grained Finance to HR Access

The policy says Finance can access the HR Server on **port 80 only** — no other access to HR. A standard ACL cannot do this because it cannot match on destination or port. We need an extended ACL.

### Placement rule for extended ACLs
> Extended ACLs should be placed **as close to the source as possible** to stop unwanted traffic early, before it consumes network bandwidth.

The source is Finance (Gi0/1). We apply the ACL **inbound on Gi0/1**.

### Write and apply Extended ACL 110
```
Router0(config)# access-list 110 remark Finance can reach HR Server on port 80 only
Router0(config)# access-list 110 permit tcp 10.0.20.0 0.0.0.255 host 10.0.10.100 eq 80

Router0(config)# access-list 110 remark Block all other Finance traffic to HR subnet
Router0(config)# access-list 110 deny ip 10.0.20.0 0.0.0.255 10.0.10.0 0.0.0.255

Router0(config)# access-list 110 remark Permit Finance to reach Guest and everything else
Router0(config)# access-list 110 permit ip any any

Router0(config)# interface GigabitEthernet0/1
Router0(config-if)# ip access-group 110 in
Router0(config-if)# exit
```

> **Order matters:** The permit for port 80 to the HR Server must come **before** the deny for the whole HR subnet. If the deny came first, port 80 traffic would be blocked before the permit rule is ever checked. ACLs are processed top-to-bottom, first match wins.

### Test Extended ACL 110
In Packet Tracer, you cannot easily test specific TCP ports with ping. Use the following approach to observe the ACL:

```
# From Finance PC0 — test ICMP (ping) to HR
C:\> ping 10.0.10.100   (HR Server)  -- should FAIL (ICMP not in the permit rule for port 80)
C:\> ping 10.0.10.10    (HR PC0)     -- should FAIL (entire HR subnet blocked for non-port-80)
C:\> ping 10.0.30.10    (Guest)      -- should SUCCEED (last permit any any)
```

Check match counters to confirm rules are being hit:
```
Router0# show access-lists 110
```

## Step 5. Block Guest from Finance

Add a standard ACL to block Guest from Finance, using the correct placement lesson from Step 3.

### Write and apply Standard ACL 20 (Guest blocked from Finance)
```
Router0(config)# access-list 20 remark Block Guest from Finance
Router0(config)# access-list 20 deny 10.0.30.0 0.0.0.255
Router0(config)# access-list 20 permit any

Router0(config)# interface GigabitEthernet0/1
Router0(config-if)# ip access-group 20 out
Router0(config-if)# exit
```

> **Note:** We now have ACL 110 applied **inbound** and ACL 20 applied **outbound** on Gi0/1. Cisco processes inbound ACLs before routing, outbound ACLs after routing. Both can coexist on the same interface in different directions.

### Test ACL 20
```
# From Guest PC0:
C:\> ping 10.0.20.10    -- should now FAIL (blocked by ACL 20)
C:\> ping 10.0.10.10    -- should still FAIL (blocked by ACL 10 from Step 2)
```

## Summary

| ACL Type | Matches On | Placement Rule | Use When |
|----------|-----------|----------------|----------|
| Standard | Source IP only | Close to destination | Blocking an entire source network from a specific destination |
| Extended | Src IP + Dst IP + Protocol + Port | Close to source | Fine-grained per-service, per-host control |

| Key Command | Purpose |
|-------------|---------|
| `access-list 10 deny 10.0.30.0 0.0.0.255` | Standard ACL — deny source subnet |
| `access-list 110 permit tcp X.X.X.X W.W.W.W host Y.Y.Y.Y eq 80` | Extended ACL — permit TCP port 80 to specific host |
| `ip access-group 10 out` | Apply ACL outbound on interface |
| `ip access-group 110 in` | Apply ACL inbound on interface |
| `show access-lists` | View all ACLs and match counters |
| `show ip interface Gi0/0` | Confirm which ACL is applied and in which direction |
| `no ip access-group 10 out` | Remove an ACL from an interface |
