# Lab 03 – DHCP, DNS & NAT/PAT

**Objective:**  
Configure three core network services on a single router acting as the default gateway — DHCP for automatic IP assignment, DNS for name resolution, and PAT for shared Internet access. You will verify each service works before moving to the next.

## Step 2. Configure Router0 Interfaces

Click **Router0** → **CLI** tab. Press **Enter** if prompted.

```
Router> enable
Router# configure terminal
Router(config)# hostname Router0

! LAN interface — default gateway for all PCs
Router0(config)# interface g0/0/0
Router0(config-if)# ip address 192.168.1.1 255.255.255.0
Router0(config-if)# no shutdown
Router0(config-if)# exit

! WAN interface — simulated Internet connection
Router0(config)# interface g0/0/1
Router0(config-if)# ip address 203.0.113.1 255.255.255.252
Router0(config-if)# no shutdown
Router0(config-if)# exit
```

**Verify both interfaces are up:**
```
Router0# show ip interface brief
```
- **Expected:** G0/0/0 and G0/0/1 both show **up/up** with correct IPs

## Step 3. Configure DHCP on Router0

The router will automatically assign IP addresses to all three PCs.

```
Router0# configure terminal

! Exclude static addresses — router, server, and reserved IPs
Router0(config)# ip dhcp excluded-address 192.168.1.1 192.168.1.5

! Create the DHCP pool
Router0(config)# ip dhcp pool LAN
Router0(dhcp-config)# network 192.168.1.0 255.255.255.0
Router0(dhcp-config)# default-router 192.168.1.1
Router0(dhcp-config)# dns-server 8.8.8.8
Router0(dhcp-config)# exit
```

> **Why exclude .1–.5?** These addresses are reserved for network infrastructure (router, server, future devices). DHCP will only assign .6 and above.

### Set PCs to use DHCP
Click each **PC** → **Desktop** tab → **IP Configuration** → select **DHCP**.

Wait a few seconds — each PC should display a `192.168.1.x` address automatically.

### Verify DHCP assignments on Router0:
```
Router0# show ip dhcp binding
```
- **Expected Output:**
```
IP address       Client-ID              Lease expiration
192.168.1.6      0060.xxxx.xxxx         --
192.168.1.7      0060.xxxx.xxxx         --
192.168.1.8      0060.xxxx.xxxx         --
```
- **Expected:** One entry per PC with addresses starting from 192.168.1.6

Also verify on any PC → **Desktop** → **Command Prompt:**
```
C:\> ipconfig
```
- **Expected:** IP in 192.168.1.0/24 range, gateway 192.168.1.1, DNS 8.8.8.8

## Step 4. Configure the DNS Server

### Set a static IP on Server0
Click **Server0** → **Desktop** tab → **IP Configuration** → select **Static**.

| Field | Value |
|-------|-------|
| IP Address | 10.0.0.100 |
| Subnet Mask | 255.255.255.0 |
| Default Gateway | 192.168.1.1 |

> **Note:** Server0 is on a different subnet (10.0.0.100) for this exercise. In a real network you would route to it — for simplicity in Packet Tracer it can be on the same switch.

### Enable the DNS service and add an A record
Click **Server0** → **Services** tab → **DNS**.

1. Toggle **DNS Service** to **On**
2. Under **Resource Records**, set:
   - **Name:** `server.local`
   - **Type:** A Record
   - **Address:** `10.0.0.100`
3. Click **Add**

### Update DHCP to point PCs at the local DNS server
```
Router0# configure terminal
Router0(config)# ip dhcp pool LAN
Router0(dhcp-config)# dns-server 10.0.0.100
Router0(dhcp-config)# exit
```

Renew DHCP on each PC to pick up the new DNS server:

Click each **PC** → **Desktop** → **IP Configuration** → click **DHCP** off then back on, or use the Command Prompt:
```
C:\> ipconfig /release
C:\> ipconfig /renew
C:\> ipconfig /all
```
- **Expected:** DNS Server now shows `10.0.0.100`

### Test name resolution
From any PC → **Desktop** → **Command Prompt:**
```
C:\> ping server.local
```
- **Expected:** Resolves to `10.0.0.100` and replies successfully
- **If it fails:** Check the DNS service is On in Server0 and the A record was saved

## Step 5. Configure PAT (NAT Overload)

PAT allows all PCs on the 192.168.1.0/24 network to share the single public IP on the router's WAN interface.

### Mark inside and outside interfaces
```
Router0# configure terminal

! LAN interface = inside (private side)
Router0(config)# interface g0/0/0
Router0(config-if)# ip nat inside
Router0(config-if)# exit

! WAN interface = outside (public side)
Router0(config)# interface g0/0/1
Router0(config-if)# ip nat outside
Router0(config-if)# exit
```

### Create an ACL to define which traffic gets translated
```
Router0(config)# access-list 1 permit 192.168.1.0 0.0.0.255
```

### Enable PAT using the WAN interface IP
```
Router0(config)# ip nat inside source list 1 interface g0/0/1 overload
```

> **What `overload` does:** Multiple private IPs are mapped to one public IP by tracking unique port numbers for each session — this is PAT (Port Address Translation).

## Step 6. Verify NAT/PAT

### Test from a PC — ping the simulated Internet
From any PC → **Desktop** → **Command Prompt:**
```
C:\> ping 203.0.113.1
```
- **Expected:** Replies from the router's WAN IP — traffic is leaving the LAN

### Check NAT translation table on Router0
```
Router0# show ip nat translations
```
- **Expected Output:**
```
Pro  Inside global     Inside local      Outside local     Outside global
icmp 203.0.113.1:1     192.168.1.6:1     203.0.113.1:1     203.0.113.1:1
```
- **Look for:** Inside local shows a `192.168.1.x` private IP; inside global shows `203.0.113.1` (the public IP)

### Check NAT statistics
```
Router0# show ip nat statistics
```
- **Look for:** Hit count incrementing — confirms translations are occurring

---

## Summary

| Concept | Description |
|---------|-------------|
| DHCP | Router automatically assigns IP, gateway, and DNS to clients |
| DHCP exclusion | Prevents DHCP from assigning addresses reserved for static devices |
| DNS A record | Maps a hostname (server.local) to an IP address (10.0.0.100) |
| NAT inside/outside | Marks which interface is private (LAN) and which is public (WAN) |
| PAT / overload | Many private IPs share one public IP using unique port numbers |
| ACL for NAT | Defines which source addresses are eligible for translation |
