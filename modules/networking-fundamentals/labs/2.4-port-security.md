# Lab 04 – Port Security & MAC Address Control

**Objective:**  
Configure port security on a Cisco switch to limit which devices can connect to each port. You will observe how the switch learns MAC addresses, set a maximum MAC limit, trigger a violation, and recover the port. You will also compare the three violation modes and understand when each is used.

## Step 4. Configure Port Security

Port security is configured per interface. You must first set the port to access mode before enabling port security.

### Enable port security on Fa0/1 (PC0 port)
```
SW0# configure terminal

SW0(config)# interface FastEthernet0/1
SW0(config-if)# switchport mode access
SW0(config-if)# switchport port-security
SW0(config-if)# switchport port-security maximum 1
SW0(config-if)# switchport port-security violation shutdown
SW0(config-if)# switchport port-security mac-address sticky
SW0(config-if)# exit
```

> **What each command does:**
> - `switchport mode access` — required before port security can be enabled
> - `switchport port-security` — enables port security on this port
> - `maximum 1` — only one MAC address is allowed on this port at a time
> - `violation shutdown` — if a second MAC is seen, the port is err-disabled immediately
> - `mac-address sticky` — the switch learns the first MAC it sees and locks it in permanently

### Apply the same configuration to Fa0/2 and Fa0/3
```
SW0(config)# interface FastEthernet0/2
SW0(config-if)# switchport mode access
SW0(config-if)# switchport port-security
SW0(config-if)# switchport port-security maximum 1
SW0(config-if)# switchport port-security violation shutdown
SW0(config-if)# switchport port-security mac-address sticky
SW0(config-if)# exit

SW0(config)# interface FastEthernet0/3
SW0(config-if)# switchport mode access
SW0(config-if)# switchport port-security
SW0(config-if)# switchport port-security maximum 1
SW0(config-if)# switchport port-security violation shutdown
SW0(config-if)# switchport port-security mac-address sticky
SW0(config-if)# exit
```

## Step 6. Trigger a Port Security Violation

Now simulate what happens when an unauthorised device is plugged into a secured port.

### Disconnect PC0 from Fa0/1
In Packet Tracer, click the cable between PC0 and SW0 and delete it.

### Connect PC1's cable to Fa0/1
- Delete the cable between PC1 and SW0 Fa0/2
- Draw a new cable from PC1 to SW0 **Fa0/1**

PC1 has a different MAC address from PC0. When PC1 sends traffic on Fa0/1, the switch sees a MAC that does not match the sticky entry — this triggers the violation.

### Send a ping from PC1 to trigger the violation
```
C:\> ping 192.168.1.1
```

### Observe the violation on SW0
```
SW0# show port-security interface FastEthernet0/1
```

**Expected output:**
```
Port Security              : Enabled
Port Status                : Secure-shutdown
Violation Mode             : Shutdown
Security Violation Count   : 1
```

Also check the interface status:
```
SW0# show ip interface brief
```
Fa0/1 should now show **down/down** — it is in err-disable state.

> **What happened:** The port was shut down the moment PC1's MAC appeared on a port locked to PC0's MAC. In a real network this would alert the security team and require manual investigation before the port is re-enabled.

## Step 7. Recover the Err-Disabled Port

A port in err-disable must be manually recovered — it will not come back on its own.

### Reconnect PC0 to Fa0/1 first
Delete the cable from PC1 to Fa0/1 and reconnect PC0 to Fa0/1.

### Recover the port on SW0
```
SW0# configure terminal
SW0(config)# interface FastEthernet0/1
SW0(config-if)# shutdown
SW0(config-if)# no shutdown
SW0(config-if)# exit
```

### Verify the port is back up
```
SW0# show port-security interface FastEthernet0/1
```
Port Status should return to **Secure-up**.

### Confirm connectivity restored
From PC0:
```
C:\> ping 192.168.1.1
```
Should succeed again.

## Step 8. Compare Violation Modes

Port security has three violation modes. Change Fa0/2 to each mode and observe the difference.

### Restrict mode — drops frames but keeps port up
```
SW0(config)# interface FastEthernet0/2
SW0(config-if)# switchport port-security violation restrict
SW0(config-if)# exit
```

Disconnect PC1 from Fa0/2, connect PC2 to Fa0/2 (different MAC), and ping:
```
C:\> ping 192.168.1.1
```
- Port stays up but traffic from the unknown MAC is dropped and a log message is generated
- `show port-security interface Fa0/2` shows violation count incrementing but port still shows Secure-up

### Protect mode — drops frames silently, no log
```
SW0(config)# interface FastEthernet0/2
SW0(config-if)# switchport port-security violation protect
SW0(config-if)# exit
```
Same behaviour as restrict but no log message — harder to detect in a real environment.

### Violation Mode Comparison Table
| Mode | Port State | Traffic Dropped | Log Generated | Use Case |
|------|-----------|-----------------|---------------|----------|
| Shutdown | err-disable | Yes | Yes (syslog) | Maximum security — strict environments |
| Restrict | Up | Yes | Yes (syslog) | Alert without disrupting the port |
| Protect | Up | Yes | No | Drop silently — rarely recommended |

> Restore Fa0/2 to shutdown mode after testing:
> ```
> SW0(config)# interface FastEthernet0/2
> SW0(config-if)# switchport port-security violation shutdown
> ```

## Reflection Questions

1. Why must a port be set to access mode before port security can be enabled?
2. What is the difference between `mac-address sticky` and manually specifying a MAC address with `mac-address xxxx.xxxx.xxxx`?
3. A help desk engineer plugs their laptop into a secured port to test something and the port shuts down. What two things need to happen before the port works again?
4. Which violation mode would you choose for a hospital where disrupting network access is more harmful than a security breach — and why?
5. Port security is configured on Fa0/1 with maximum 2. A hub is connected to that port with three PCs. What happens?

---

## Summary

| Concept | Description |
|---------|-------------|
| Port security | Limits which MAC addresses are allowed on a switch port |
| Sticky MAC | Switch dynamically learns and permanently locks the first MAC it sees |
| Maximum | Maximum number of MAC addresses allowed on a port at once |
| Shutdown | Port goes err-disabled on violation — requires manual recovery |
| Restrict | Port stays up, unknown traffic dropped, violation logged |
| Protect | Port stays up, unknown traffic dropped silently — no log |
| Err-disable recovery | `shutdown` then `no shutdown` on the interface |
