## Step 4. Configure DHCP Relay on Router0

DHCP uses broadcasts which routers block by default. The `ip helper-address` command forwards DHCP requests from LAN1 PCs across the router to Server0.

```
Router0# configure terminal

! Forward LAN1 DHCP broadcasts to Server0
Router0(config)# interface g0/0/0
Router0(config-if)# ip helper-address 192.168.0.66
Router0(config-if)# exit
```

> **Why only LAN1?** Server0 is on LAN2 so LAN2 PCs can reach it directly. LAN1 PCs are on a different subnet and need the relay to cross Router0.

### Set PCs to use DHCP
Click each **PC** → **Desktop** tab → **IP Configuration** → select **DHCP**.

Wait a few seconds — each PC should receive an IP address automatically.

### Verify DHCP on Server0:
Click **Server0** → **Services** → **DHCP** → check the binding table at the bottom of the page.

Also verify from any PC:
```
C:\> ipconfig /all
```
- **Expected:** IP in correct subnet range, gateway and DNS matching the pool values

## Step 5. Configure PAT (Internet Access for All PCs)

PAT allows all private IPs on both LAN subnets to share the single public IP on Router0's WAN interface.

```
Router0# configure terminal

! Mark interfaces
Router0(config)# interface g0/0/0
Router0(config-if)# ip nat inside
Router0(config-if)# exit

Router0(config)# interface g0/0/1
Router0(config-if)# ip nat inside
Router0(config-if)# exit

Router0(config)# interface g0/0/2
Router0(config-if)# ip nat outside
Router0(config-if)# exit

! ACL to define which traffic gets translated
Router0(config)# access-list 10 permit 192.168.0.0 0.0.0.63
Router0(config)# access-list 10 permit 192.168.0.64 0.0.0.31

! Enable PAT using the WAN interface
Router0(config)# ip nat inside source list 10 interface g0/0/2 overload
```

---

## Step 6. Configure Static NAT (Inbound Access to Server0)

Static NAT creates a permanent one-to-one mapping so external hosts can always reach Server0 at a fixed public IP.

```
Router0(config)# ip nat inside source static 192.168.0.66 192.168.0.97
```

> **What this does:** Any traffic arriving on the WAN interface destined for 192.168.0.97 (the router's public IP) gets forwarded to Server0 at 192.168.0.66 on LAN2.

---

## Step 7. Configure the ACL

Deny Telnet from LAN2 to LAN1 — permit everything else.

```
Router0(config)# ip access-list extended BLOCK_TELNET
Router0(config-ext-nacl)# deny tcp 192.168.0.64 0.0.0.31 192.168.0.0 0.0.0.63 eq 23
Router0(config-ext-nacl)# permit ip any any
Router0(config-ext-nacl)# exit

! Apply inbound on LAN2 interface — catches traffic from LAN2 as it enters the router
Router0(config)# interface g0/0/1
Router0(config-if)# ip access-group BLOCK_TELNET in
Router0(config-if)# exit
```

Work through each verification test below in order. Every test must pass before moving to the documentation step.

```
C:\> ping 192.168.0.66

```

### PAT — Internet access
From any PC:
```
C:\> ping 192.168.0.98
```
Then on Router0:
```
Router0# show ip nat translations
```
- **Expected:** Inside local shows `192.168.0.x`, inside global shows `192.168.0.97`

### Static NAT — inbound to server
```
Router0# show ip nat translations
```
- **Expected:** A static entry mapping `192.168.0.97` ↔ `192.168.0.66`

### ACL — Telnet blocked from LAN2 to LAN1
From a LAN2 device (Server0) → **Desktop** → **Command Prompt:**
```
C:\> telnet 192.168.0.1
```
- **Expected:** Connection times out — blocked by ACL

```
C:\> ping 192.168.0.1
```
- **Expected:** Replies — ICMP is still permitted

Confirm on Router0:
```
Router0# show ip access-lists BLOCK_TELNET
```
- **Expected:** Non-zero match count on the deny line

### Routing table — all networks present
```
Router0# show ip route
```
- **Expected:** Connected routes for 192.168.0.0/26, 192.168.0.64/27, and 192.168.0.96/30
