# Lab 10 – OSPF Single-Area Configuration

**Objective:**  
Replace all static routes from Lab 09 with OSPF and verify that the routers learn each other's networks automatically. You will also test OSPF's convergence — shut a link and watch OSPF re-route around the failure within seconds.

> **Prerequisite:** Complete Lab 09 first. This lab uses the exact same topology and IP addresses.

---

## Topology

Same as Lab 09 — three routers in a chain with two PCs.

```
[PC-A]──[SW-A]──[R1]──10.0.12.0/30──[R2]──10.0.23.0/30──[R3]──[SW-C]──[PC-C]
         192.168.1.0/24                                        192.168.3.0/24
```

### OSPF Network Summary
| Router | Networks to Advertise | Area |
|--------|----------------------|------|
| R1 | 192.168.1.0/24, 10.0.12.0/30 | 0 |
| R2 | 10.0.12.0/30, 10.0.23.0/30 | 0 |
| R3 | 10.0.23.0/30, 192.168.3.0/24 | 0 |

## Step 1. Remove All Static Routes

Before configuring OSPF, remove every static route added in Lab 09. If static routes remain they will win over OSPF (AD 1 beats AD 110) and mask whether OSPF is working.

### R1
```
R1(config)# no ip route 10.0.23.0 255.255.255.252 10.0.12.2
R1(config)# no ip route 192.168.3.0 255.255.255.0 10.0.12.2
```

### R2
```
R2(config)# no ip route 192.168.1.0 255.255.255.0 10.0.12.1
R2(config)# no ip route 192.168.3.0 255.255.255.0 10.0.23.2
```

### R3
```
R3(config)# no ip route 10.0.12.0 255.255.255.252 10.0.23.1
R3(config)# no ip route 192.168.1.0 255.255.255.0 10.0.23.1
```

### Confirm routes are gone
```
R1# show ip route
```
You should see only C and L routes — no S entries. Ping from PC-A to PC-C should now fail.

```
C:\> ping 192.168.3.10   ← should fail — no routes
```

## Step 2. Configure OSPF

### R1
```
R1(config)# router ospf 1
R1(config-router)# network 192.168.1.0 0.0.0.255 area 0
R1(config-router)# network 10.0.12.0 0.0.0.3 area 0
R1(config-router)# exit
```

### R2
```
R2(config)# router ospf 1
R2(config-router)# network 10.0.12.0 0.0.0.3 area 0
R2(config-router)# network 10.0.23.0 0.0.0.3 area 0
R2(config-router)# exit
```

### R3
```
R3(config)# router ospf 1
R3(config-router)# network 10.0.23.0 0.0.0.3 area 0
R3(config-router)# network 192.168.3.0 0.0.0.255 area 0
R3(config-router)# exit
```

> **Wildcard mask reminder:** The wildcard is the inverse of the subnet mask. /24 = 0.0.0.255 (last octet all ones). /30 = 0.0.0.3 (last 2 bits all ones). Any interface whose IP falls in that range gets included in OSPF.

> **Process ID:** The 1 in `router ospf 1` is a local process ID — it does not need to match between routers.

---

## Step 3. Suppress Hellos on LAN Interfaces

R1 and R3 have LAN interfaces (Gi0/2) facing switches and PCs. There are no OSPF neighbours on those ports, so sending hellos is pointless. Use passive-interface to suppress hellos while still advertising the connected subnet.

```
R1(config)# router ospf 1
R1(config-router)# passive-interface GigabitEthernet0/2
R1(config-router)# exit

R3(config)# router ospf 1
R3(config-router)# passive-interface GigabitEthernet0/2
R3(config-router)# exit
```

## Step 5. Verify OSPF Routes

```
R1# show ip route ospf
```

**Expected output:**
```
O    10.0.23.0/30  [110/2] via 10.0.12.2, GigabitEthernet0/0
O    192.168.3.0/24 [110/3] via 10.0.12.2, GigabitEthernet0/0
```

> **Reading the metric:** [110/2] means AD=110 (OSPF) and cost=2. Each hop across a GigabitEthernet link adds a cost of 1 by default. R3's LAN is 3 hops away from R1 so cost=3.

### Compare to Lab 09
| Route | Lab 09 (Static) | Lab 10 (OSPF) | AD | Code |
|-------|----------------|----------------|-----|------|
| 192.168.3.0/24 | S via 10.0.12.2 | O via 10.0.12.2 | 1 → 110 | S → O |
| 10.0.23.0/30 | S via 10.0.12.2 | O via 10.0.12.2 | 1 → 110 | S → O |

## Step 7. Test OSPF Failover

This is the key advantage of OSPF over static routes. Shut a link and watch OSPF reconverge automatically.

### Shut the R1–R2 link
On R1:
```
R1(config)# interface GigabitEthernet0/0
R1(config-if)# shutdown
```

### Immediately ping from PC-A
```
C:\> ping 192.168.3.10
```
The first few pings will fail while OSPF reconverges (dead interval is 40 seconds by default in Packet Tracer). After reconvergence, OSPF will have removed the route since there is no alternate path in this topology — pings will fail.

### Bring the link back up
```
R1(config-if)# no shutdown
```

Wait for OSPF to re-form the adjacency (watch for FULL state):
```
R1# show ip ospf neighbor
```

Once Full is restored, ping PC-C again — should succeed.

> **Why no failover?** In this linear topology there is only one path. In a real network with redundant links OSPF would automatically reroute around the failure. Lab 11 adds a redundant path so you can observe true failover.

## Summary

| Key Command | Purpose |
|-------------|---------|
| `router ospf 1` | Start OSPF process (1 = local ID only) |
| `network X.X.X.X W.W.W.W area 0` | Advertise network into area 0 |
| `passive-interface Gi0/2` | Suppress hellos, keep advertising |
| `show ip ospf neighbor` | Check adjacency state |
| `show ip ospf database` | View LSDB |
| `show ip route ospf` | View only OSPF-learned routes |
| `show ip ospf interface Gi0/0` | Hello/dead timers, cost, DR/BDR |
