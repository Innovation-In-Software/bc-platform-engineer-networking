# Lab 8 – Two-Site Office Network: VLANs, HSRP & OSPF

**Objective:**  
Build a two-site office network with redundant gateways at Site A and dynamic routing between sites. Site A has two department VLANs with HSRP providing failover. Site B has a server subnet. OSPF connects the two sites so routes are learned automatically. Both Site A routers have their own WAN link to Site B so failover is complete end-to-end.

---

## Topology

```
[HR-PC0]──Fa0/1──┐
[HR-PC1]──Fa0/2──┤                      ┌──Fa0/1──[Server0]
                 ├──[SW-A]──Fa0/24──[R-Primary]──G0/1──G0/0──[R-SiteB]──G0/1──[SW-B]
[FIN-PC0]──Fa0/3─┤          Fa0/23──[R-Standby]──G0/1──G0/2──┘          Fa0/24
[FIN-PC1]──Fa0/4─┘
```

- R-Primary connects to Site B via G0/1 → R-SiteB G0/0
- R-Standby connects to Site B via G0/1 → R-SiteB G0/2
- Both WAN links run OSPF so either router can reach Site B independently

## Step 2. Configure SW-A

```
Switch> enable
Switch# configure terminal
Switch(config)# hostname SW-A

SW-A(config)# vlan 10

SW-A(config-vlan)# exit

SW-A(config)# interface FastEthernet0/1
SW-A(config-if)# switchport mode access
SW-A(config-if)# switchport access vlan 10
SW-A(config-if)# exit

SW-A(config)# interface FastEthernet0/2
SW-A(config-if)# switchport mode access
SW-A(config-if)# switchport access vlan 10
SW-A(config-if)# exit

SW-A(config)# interface FastEthernet0/3
SW-A(config-if)# switchport mode access
SW-A(config-if)# switchport access vlan 20
SW-A(config-if)# exit

SW-A(config)# interface FastEthernet0/4
SW-A(config-if)# switchport mode access
SW-A(config-if)# switchport access vlan 20
SW-A(config-if)# exit

SW-A(config)# interface FastEthernet0/24
SW-A(config-if)# switchport mode trunk

## Step 6. Configure HSRP

### On R-Primary (Active for both VLANs)
```
R-Primary(config)# interface GigabitEthernet0/0.10
R-Primary(config-subif)# standby 10 ip 192.168.10.1
R-Primary(config-subif)# standby 10 priority 110
R-Primary(config-subif)# standby 10 preempt
R-Primary(config-subif)# exit

R-Primary(config)# interface GigabitEthernet0/0.20
R-Primary(config-subif)# standby 20 ip 192.168.20.1
R-Primary(config-subif)# standby 20 priority 110
R-Primary(config-subif)# standby 20 preempt
R-Primary(config-subif)# exit
```

### On R-Standby (Standby for both VLANs)
```
R-Standby(config)# interface GigabitEthernet0/0.10
R-Standby(config-subif)# standby 10 ip 192.168.10.1
R-Standby(config-subif)# standby 10 priority 100
R-Standby(config-subif)# exit

R-Standby(config)# interface GigabitEthernet0/0.20
R-Standby(config-subif)# standby 20 ip 192.168.20.1
R-Standby(config-subif)# standby 20 priority 100
R-Standby(config-subif)# exit
```

### Verify HSRP
```
R-Primary# show standby brief
R-Standby# show standby brief
```
- R-Primary shows Active for groups 10 and 20
- R-Standby shows Standby for groups 10 and 20

## Step 8. Configure OSPF

All three routers run OSPF in area 0 so routes are shared automatically.

### R-Primary
```
R-Primary(config)# router ospf 1
R-Primary(config-router)# network 192.168.10.0 0.0.0.255 area 0
R-Primary(config-router)# network 192.168.20.0 0.0.0.255 area 0
R-Primary(config-router)# network 10.0.12.0 0.0.0.3 area 0
R-Primary(config-router)# passive-interface GigabitEthernet0/0.10
R-Primary(config-router)# passive-interface GigabitEthernet0/0.20
R-Primary(config-router)# exit
```

### R-Standby
```
R-Standby(config)# router ospf 1
R-Standby(config-router)# network 192.168.10.0 0.0.0.255 area 0
R-Standby(config-router)# network 192.168.20.0 0.0.0.255 area 0
R-Standby(config-router)# network 10.0.13.0 0.0.0.3 area 0
R-Standby(config-router)# passive-interface GigabitEthernet0/0.10
R-Standby(config-router)# passive-interface GigabitEthernet0/0.20
R-Standby(config-router)# exit
```

### R-SiteB
```
R-SiteB(config)# router ospf 1
R-SiteB(config-router)# network 10.0.12.0 0.0.0.3 area 0
R-SiteB(config-router)# network 10.0.13.0 0.0.0.3 area 0
R-SiteB(config-router)# network 192.168.30.0 0.0.0.255 area 0
R-SiteB(config-router)# passive-interface GigabitEthernet0/1
R-SiteB(config-router)# exit
```

### Verify OSPF
```
R-Primary# show ip ospf neighbor
R-Primary# show ip route ospf
```
- R-Primary should show FULL adjacency with R-SiteB
- R-Primary routing table should show an O route for 192.168.30.0/24
- R-Standby should show FULL adjacency with R-SiteB

## Step 10. Test HSRP Failover with End-to-End Verification

This step confirms that when R-Primary fails, R-Standby takes over and traffic to Site B continues through R-Standby's own WAN link.

### 1. Confirm baseline on both routers
```
R-Primary# show standby brief
R-Standby# show standby brief

```

### 2. Simulate R-Primary failure
```
R-Primary(config)# interface GigabitEthernet0/0

```

### 3. Check HSRP has failed over
```
R-Standby# show standby brief
```
R-Standby should now show Active for both groups.

### 4. Test connectivity to Site B still works
From HR-PC0:
```
C:\> ping 192.168.30.10

### 5. Restore R-Primary and observe preemption
```
R-Primary(config-if)# no shutdown
```
Wait a few seconds then:
```
R-Primary# show standby brief
```
R-Primary should reclaim Active automatically.

## Reflection Questions

1. R-Primary and R-Standby both advertise 192.168.10.0/24 and 192.168.20.0/24 into OSPF. Does R-SiteB have two routes to each of those subnets in its routing table — and how does it choose which one to use?
2. Why does R-Primary need passive-interface on its VLAN sub-interfaces but not on G0/1?
3. After R-Primary fails, R-Standby becomes the Active HSRP gateway. Traffic to Site B now flows through R-Standby's WAN link (10.0.13.0/30). How does R-SiteB know to send return traffic back through that link instead of the now-dead 10.0.12.0/30 link?
4. DHCP is only on R-Primary. When R-Standby takes over as Active gateway, existing PCs keep their leases and can still communicate. But what happens when a lease expires or a new PC joins the network during the outage?
5. You have configured OSPF process ID 1 on all three routers. Does the process ID need to match between routers for OSPF to work?

## Summary

| Technology | Where | Purpose |
|-----------|-------|---------|
| VLANs + Trunking | SW-A | Separate HR and Finance broadcast domains |
| ROAS | R-Primary, R-Standby | Route between VLANs over trunk links |
| HSRP | R-Primary (Active), R-Standby (Standby) | Redundant default gateway for Site A |
| DHCP | R-Primary | Automatic IP assignment for all Site A clients |
| OSPF | R-Primary, R-Standby, R-SiteB | Dynamic routing between sites |
| Dual WAN links | R-Primary G0/1 and R-Standby G0/1 | Ensures Site B is reachable after failover |
