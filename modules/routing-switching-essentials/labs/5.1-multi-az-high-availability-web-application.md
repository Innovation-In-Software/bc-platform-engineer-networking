# Lab 01 – Multi-AZ High Availability Web Application

**Objective:**  
Deploy a web application that automatically scales and stays online even if an Availability Zone (AZ) fails.  
You will use an **Auto Scaling Group (ASG)** across multiple AZs with a new **Application Load Balancer (ALB)**.

## Before You Start — Confirm Existing Resources

This lab uses **TrainingVPC** and both public subnets created in earlier labs. Confirm the following exist before proceeding:

| Resource | Name | CIDR / AZ |
|----------|------|-----------|
| VPC | TrainingVPC | 10.0.0.0/16 |
| Public Subnet | PublicSubnetA | 10.0.1.0/24 — us-east-1a |
| Public Subnet | PublicSubnetB | 10.0.20.0/24 — us-east-1b |
| Internet Gateway | TrainingIGW | Attached to TrainingVPC |
| Route Table | PublicRT | 0.0.0.0/0 → TrainingIGW |

To check: go to **VPC → Subnets** and confirm both subnets are listed.

> **If PublicSubnetB does not exist**, go back to the previous lab (Load-Balanced Web Tier, Step 1) and create it before continuing.

> **Note:** This lab creates a **new** ALB (`WebAppALB`) and a **new** target group (`WebAppTG`) separate from the `TrainingALB` used in the previous lab. Do not reuse or modify `TrainingALB`.

---

## Step 1 – Create a Security Group for ASG Instances

Before creating the Launch Template you need a security group to attach to instances.

1. Go to **EC2 → Security Groups → Create Security Group**.
2. Configure:
   - **Name:** `WebAppSG`
   - **Description:** `Allow HTTP and SSH for ASG instances`
   - **VPC:** `TrainingVPC`
3. Add inbound rules:

   | Type | Protocol | Port | Source |
   |------|----------|------|--------|
   | SSH | TCP | 22 | My IP |
   | HTTP | TCP | 80 | 0.0.0.0/0 |

4. Leave outbound as default (Allow All).
5. Click **Create security group**.

---

## Step 2 – Create a Launch Template

The Launch Template defines what every instance the ASG creates will look like.

1. Navigate to **EC2 → Launch Templates → Create Launch Template**.
2. Configure:
   - **Name:** `WebAppTemplate`
   - **AMI:** Amazon Linux 2023
   - **Instance type:** t2.micro
   - **Key pair:** same key used in previous labs
3. Under **Network settings**:
   - Do **not** specify a subnet here — the ASG will control subnet placement
   - **Security Group:** select `WebAppSG`
4. Under **Advanced details → User data**, paste:

```bash
#!/bin/bash
sudo yum install -y httpd
AZ=$(curl -s http://169.254.169.254/latest/meta-data/placement/availability-zone)
echo "Hello from $(hostname) in $AZ" | sudo tee /var/www/html/index.html
sudo systemctl start httpd
sudo systemctl enable httpd
```

5. Click **Create launch template**.

> **What the user data does:** Installs Apache, writes a page showing the instance hostname and AZ, and starts the web server. This lets you see which AZ each response comes from when testing the ALB.

---

## Step 3 – Create an Auto Scaling Group

1. Go to **EC2 → Auto Scaling Groups → Create Auto Scaling Group**.
2. Configure:
   - **Name:** `WebAppASG`
   - **Launch template:** `WebAppTemplate`
3. Click **Next**.
4. Under **Network**:
   - **VPC:** `TrainingVPC`
   - **Subnets:** select both `PublicSubnetA (us-east-1a)` and `PublicSubnetB (us-east-1b)`
5. Click **Next**.
6. Under **Load balancing**:
   - Select **Attach to a new load balancer**
   - **Load balancer type:** Application Load Balancer
   - **Load balancer name:** `WebAppALB`
   - **Load balancer scheme:** Internet-facing
   - **Listeners and routing:** HTTP:80 → create a new target group named `WebAppTG`
   - **Availability Zones and subnets:** confirm both PublicSubnetA and PublicSubnetB are selected
7. Under **Health checks**:
   - Enable **ELB health checks** in addition to EC2
8. Click **Next**.
9. Under **Group size**:
   - **Desired capacity:** 2
   - **Minimum capacity:** 1
   - **Maximum capacity:** 3
10. Click through remaining steps → **Create Auto Scaling Group**.

✅ The ASG will launch two instances — one in each AZ — and register them with WebAppALB automatically.

---

## Step 4 – Wait for Instances and Health Checks

1. Go to **EC2 → Instances** — you should see two new instances launching with names like `WebAppASG`.
2. Wait for both to show **Instance State: Running** and **Status Checks: 2/2 passed**.
3. Go to **EC2 → Target Groups → WebAppTG → Targets** tab.
4. Wait until both targets show **Health status: Healthy**.

> **If targets stay unhealthy**, check that `WebAppSG` has HTTP port 80 open to `0.0.0.0/0` and that the user data script ran correctly by SSHing in and running `curl http://localhost`.

---

## Step 5 – Test High Availability

### Test 1: Confirm load balancing across AZs
1. Go to **EC2 → Load Balancers → WebAppALB** — copy the **DNS name**.
2. Open in your browser:
   ```
   http://WebAppALB-xxxx.us-east-1.elb.amazonaws.com
   ```
3. Refresh several times — you should see responses alternating between AZs:
   - `Hello from ip-10-0-1-xx in us-east-1a`
   - `Hello from ip-10-0-20-xx in us-east-1b`

✅ ALB is distributing traffic evenly across both AZs.

### Test 2: Simulate AZ failure and auto-recovery
1. Go to **EC2 → Instances** — select one of the ASG instances → **Instance State → Stop**.
2. Refresh your browser — all responses should now come from the remaining instance with no error page.
3. Go to **EC2 → Auto Scaling Groups → WebAppASG → Activity** tab.
4. You should see a new launch event — the ASG is replacing the stopped instance automatically.
5. Wait ~2 minutes then check **Instances** — a new instance will appear in the same AZ.

✅ ASG detected the unhealthy instance and launched a replacement automatically.

## Verification Checklist

| Check | Expected Result |
|-------|-----------------|
| Two instances launched by ASG | One in each AZ |
| Both targets in WebAppTG | Health status: Healthy |
| ALB DNS in browser | Returns response from one of the instances |
| Responses alternate on refresh | Shows different hostnames and AZs |
| After stopping one instance | Browser continues to load with no error |
| ASG Activity tab | Shows a new launch event |
| After ~2 minutes | Replacement instance running and healthy |

---

## Key Takeaways

| Concept | Description |
|---------|-------------|
| Multi-AZ | Fault tolerance across data centers within one region |
| Launch Template | Defines the blueprint for every instance the ASG creates |
| Auto Scaling Group | Maintains desired instance count — replaces unhealthy instances automatically |
| ALB + ASG | ALB detects unhealthy targets; ASG replaces them — together they eliminate single points of failure |
| Health checks | ELB health checks are stricter than EC2 checks — use both for reliable auto-recovery |
