# Lab 01 – Configuring DNS with Amazon Route 53

**Objective:**  
Understand how to manage DNS in AWS by creating hosted zones and records in Route 53.  
You'll configure a custom domain to point to your existing web server and test resolution using the AWS DNS infrastructure.

---

## Topology

```
Browser ⇄ Route 53 ⇄ WebServer (EC2 in VPC)
```

> This lab continues from **Lab 00, 01, and 02** of the previous module. You will use the **WebServer** EC2 instance and **TrainingVPC** already in place. No new instances are needed.

---

## Before You Start — Confirm Existing Resources

| Resource | Name | What You Need |
|----------|------|---------------|
| EC2 Instance | WebServer | Running — note its **public IP** |
| EC2 Instance | DBServer | Running — note its **private IP** |
| VPC | TrainingVPC | Available |

To find the IPs: go to **EC2 → Instances** → select each instance → note the **Public IPv4 address** (WebServer) and **Private IPv4 address** (DBServer).

---

## Step 1 – Create a Hosted Zone

### Option A: If You Own a Domain
1. Go to **Route 53 → Hosted Zones → Create Hosted Zone**
2. Configuration:
   - **Domain name:** `yourdomain.com` *(your actual domain)*
   - **Type:** Public Hosted Zone
   - **VPC association:** leave blank for public zones

### Option B: If You Don't Own a Domain (Recommended for Lab)
1. Go to **Route 53 → Hosted Zones → Create Hosted Zone**
2. Configuration:
   - **Domain name:** `training-lab-[YOUR-INITIALS].example` *(e.g. `training-lab-jd.example`)*
   - **Type:** Public Hosted Zone
   - **VPC association:** leave blank for public zones

> **Note:** `.example` domains won't resolve from the public internet, but you can still practice all Route 53 configuration steps and test within your VPC.

### Option C: Private Hosted Zone Only
Skip to **Step 3** to work with private DNS resolution inside your VPC only — no domain required.

✅ After creation you will see four **NS** records and one **SOA** record automatically created. This is normal.

---

## Step 2 – Add DNS Records

### A Record — point to WebServer
1. In your hosted zone, click **Create record**.
2. Configure:
   - **Record name:** `www`
   - **Record type:** A
   - **Value:** WebServer's **public IP address** (from the Before You Start section above)
   - **TTL:** 300
3. Click **Create records**.

### CNAME Record — create an alias
1. Click **Create record** again.
2. Configure:
   - **Record name:** `app`
   - **Record type:** CNAME
   - **Value:** `www.training-lab-[YOUR-INITIALS].example` *(point to the A record you just created)*
   - **TTL:** 300
3. Click **Create records**.

### Examples by option chosen in Step 1:
| Option | A Record Points To | CNAME Points To |
|--------|-------------------|-----------------|
| Real domain | WebServer public IP | `www.yourdomain.com` |
| Example domain | WebServer public IP | `www.training-lab-xx.example` |
| Private only | Skip this step | Skip this step |

---

## Step 3 – Create a Private Hosted Zone

This step works for **everyone** regardless of whether you own a domain — private DNS resolves only inside the VPC.

1. Go to **Route 53 → Hosted Zones → Create Hosted Zone**.
2. Configure:
   - **Domain name:** `internal.training`
   - **Type:** Private Hosted Zone
   - **VPC region:** your region (e.g. us-east-1)
   - **VPC:** `TrainingVPC`
3. Click **Create hosted zone**.
4. Click **Create record** and add:
   - **Record name:** `db`
   - **Record type:** A
   - **Value:** DBServer's **private IP address**
   - **TTL:** 300
5. Click **Create records**.

✅ `db.internal.training` will now resolve to DBServer's private IP — but only from within TrainingVPC.

---

## Step 4 – Test DNS Resolution

### Test 1: Private DNS (works for everyone)
SSH into WebServer, then run:
```bash
# Test private DNS resolution
nslookup db.internal.training

# Test connectivity using the DNS name
ping db.internal.training
```
✅ Expected: resolves to DBServer's private IP and ping succeeds.

### Test 2: Direct IP access (fallback test)
```bash
# From any EC2 in the VPC
curl http://[WebServer-Private-IP]
```
✅ Expected: returns the web page content.

### Test 3: Public domain (Option A users only)
From your local machine:
```bash
nslookup www.yourdomain.com
ping www.yourdomain.com
```
✅ Expected: resolves to WebServer's public IP.

### Test 4: Example domain (Option B users — from EC2 only)
SSH into WebServer, then run:
```bash
nslookup www.training-lab-[YOUR-INITIALS].example
```
> Note: This may or may not resolve depending on AWS resolver behaviour for `.example` domains. The important verification is that the records exist correctly in the Route 53 console.

## Optional Enhancement — Add an Alias Record for ALB

> **Complete Lab 02 (Load-Balanced Web Tier) first**, then return here to add this record.

Once you have an ALB from Lab 02, you can point a DNS name at it using an Alias record — no IP address needed.

1. Go to your hosted zone → **Create record**.
2. Configure:
   - **Record name:** `www`
   - **Record type:** A
   - Toggle **Alias** on
   - **Route traffic to:** Application and Classic Load Balancer
   - **Region:** your region
   - **Load balancer:** select `TrainingALB`
3. Click **Create records**.

This replaces the static WebServer IP with a load balancer endpoint — DNS now points at a highly available target instead of a single instance.

```bash
# Test from local machine or EC2
curl http://www.training-lab-[YOUR-INITIALS].example
```

✅ Expected: returns responses from both WebServer and WebServer2 alternately.
