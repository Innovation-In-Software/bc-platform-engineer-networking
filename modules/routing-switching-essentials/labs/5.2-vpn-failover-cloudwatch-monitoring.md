# Lab 02 – VPN Failover and CloudWatch Monitoring

**Objective:**  
Simulate redundancy in hybrid connectivity using **AWS Site-to-Site VPN**.  
You'll configure a VPN between two VPCs — one acting as the AWS side and one simulating an on-premises network using a software VPN on EC2 — then monitor tunnel state with **CloudWatch metrics**.

---

## Topology

```
SimulatedOnPremVPC (192.168.0.0/16)        TrainingVPC (10.0.0.0/16)
┌──────────────────────────┐              ┌────────────────────────┐
│  OnPremServer (EC2)      │              │  Virtual Private       │
│  StrongSwan VPN client   │◄────VPN─────►│  Gateway (VGW)         │
│  192.168.1.10            │   2 tunnels  │                        │
│  has Elastic IP          │              │                        │
└──────────────────────────┘              └────────────────────────┘
                                                      │
                                              CloudWatch Alarms
                                              (TunnelState metric)
```

> **Why use an EC2 instance instead of real hardware?**  
> A real Site-to-Site VPN requires a physical VPN device with a static public IP at the customer side. In a classroom environment we simulate the on-premises side using a **StrongSwan** software VPN running on an EC2 instance with an Elastic IP. This gives the same AWS-side configuration experience and lets you observe CloudWatch tunnel metrics.

## Step 1 – Create the Simulated On-Premises VPC

This VPC represents your on-premises network.

1. Go to **VPC → Create VPC**.
2. Configure:
   - **Name:** `SimulatedOnPremVPC`
   - **IPv4 CIDR:** `192.168.0.0/16`
3. Click **Create VPC**.

### Create a subnet
4. Go to **VPC → Subnets → Create Subnet**.
5. Configure:
   - **VPC:** `SimulatedOnPremVPC`
   - **Subnet name:** `OnPremSubnet`
   - **Availability Zone:** us-east-1a
   - **IPv4 CIDR:** `192.168.1.0/24`
6. Enable auto-assign public IPv4 on this subnet.

### Create and attach an Internet Gateway
7. Go to **VPC → Internet Gateways → Create internet gateway**.
   - **Name:** `OnPremIGW`
8. Select it → **Actions → Attach to VPC → SimulatedOnPremVPC**.
9. Go to **VPC → Route Tables** → find the route table for `SimulatedOnPremVPC` → **Routes → Edit routes → Add route**:
   - **Destination:** `0.0.0.0/0`
   - **Target:** `OnPremIGW`

---

## Step 2 – Launch the On-Premises VPN Server

1. Go to **EC2 → Launch Instance**.
2. Configure:
   - **Name:** `OnPremServer`
   - **AMI:** Amazon Linux 2023
   - **Instance type:** t2.micro
   - **Key pair:** same key as previous labs
3. Under **Network settings → Edit**:
   - **VPC:** `SimulatedOnPremVPC`
   - **Subnet:** `OnPremSubnet`
   - **Auto-assign public IP:** Enable
4. Under **Security Group**, create new:
   - **Name:** `OnPremSG`
   - Rules:

   | Type | Protocol | Port | Source |
   |------|----------|------|--------|
   | SSH | TCP | 22 | My IP |
   | Custom UDP | UDP | 500 | 0.0.0.0/0 |
   | Custom UDP | UDP | 4500 | 0.0.0.0/0 |
   | All ICMP - IPv4 | ICMP | All | 10.0.0.0/16 |

   > UDP 500 and 4500 are required for IKE (VPN key exchange) and IPsec NAT traversal.

5. Click **Launch instance**.

### Allocate and associate an Elastic IP
The Customer Gateway in AWS requires a **static** public IP — Elastic IP provides this.

6. Go to **EC2 → Elastic IPs → Allocate Elastic IP address → Allocate**.
7. Select the new Elastic IP → **Actions → Associate Elastic IP address**.
8. Configure:
   - **Resource type:** Instance
   - **Instance:** `OnPremServer`
9. Click **Associate**.
10. Note the Elastic IP address — you will need it in Step 3.

---

## Step 3 – Create the Virtual Private Gateway (VGW)

The VGW is the AWS side of the VPN connection, attached to TrainingVPC.

1. Go to **VPC → Virtual Private Gateways → Create virtual private gateway**.
2. Configure:
   - **Name:** `TrainingVGW`
   - **ASN:** leave as Amazon default ASN
3. Click **Create virtual private gateway**.
4. Select `TrainingVGW` → **Actions → Attach to VPC → TrainingVPC → Yes, Attach**.

✅ VGW is now attached to TrainingVPC.

---

## Step 4 – Create the Customer Gateway (CGW)

The CGW represents the on-premises VPN device — in our case, the OnPremServer's Elastic IP.

1. Go to **VPC → Customer Gateways → Create Customer Gateway**.
2. Configure:
   - **Name:** `OnPremCGW`
   - **Routing:** Static
   - **IP address:** paste the **Elastic IP** from Step 2
3. Click **Create customer gateway**.

---

## Step 5 – Create the Site-to-Site VPN Connection

1. Go to **VPC → Site-to-Site VPN Connections → Create VPN Connection**.
2. Configure:
   - **Name:** `TrainingVPN`
   - **Target gateway type:** Virtual Private Gateway → select `TrainingVGW`
   - **Customer gateway:** Existing → select `OnPremCGW`
   - **Routing options:** Static
   - **Static IP prefixes:** `192.168.1.0/24` (the on-prem subnet)
3. Click **Create VPN Connection**.

> VPN creation takes 2–5 minutes. The status will show **Pending** then **Available**.

### Download the configuration file
4. Select `TrainingVPN` → **Download Configuration**.
5. Configure:
   - **Vendor:** Generic
   - **Platform:** Generic
   - **Software:** Vendor Agnostic
6. Click **Download** — open the file and note:
   - **Outside IP Address** for Tunnel 1 and Tunnel 2 (AWS public IPs)
   - **Pre-Shared Key** for each tunnel
   - **Inside IP addresses** for each tunnel

## Step 6 – Configure StrongSwan on OnPremServer

SSH into OnPremServer using its Elastic IP:
```bash
ssh -i MyAWSKey.pem ec2-user@<OnPremServer_Elastic_IP>
```

Install StrongSwan:
```bash
sudo yum install -y strongswan
```

Configure the VPN using values from the downloaded configuration file.  
Edit the IPsec secrets file:
```bash
sudo nano /etc/strongswan/ipsec.secrets
```
Add (replace with values from your downloaded config):
```
<OnPremServer_Elastic_IP> <Tunnel1_AWS_Outside_IP> : PSK "<Tunnel1_Pre_Shared_Key>"
<OnPremServer_Elastic_IP> <Tunnel2_AWS_Outside_IP> : PSK "<Tunnel2_Pre_Shared_Key>"
```

Edit the IPsec config file:
```bash
sudo nano /etc/strongswan/ipsec.conf
```
Add:
```
conn Tunnel1
    authby=secret
    auto=start
    left=%defaultroute
    leftid=<OnPremServer_Elastic_IP>
    right=<Tunnel1_AWS_Outside_IP>
    type=tunnel
    ikelifetime=8h
    keylife=1h
    phase2alg=aes128-sha1-modp1024
    ike=aes128-sha1-modp1024
    leftsubnet=192.168.1.0/24
    rightsubnet=10.0.0.0/16
    dpddelay=10
    dpdtimeout=30
    dpdaction=restart

conn Tunnel2
    authby=secret
    auto=start
    left=%defaultroute
    leftid=<OnPremServer_Elastic_IP>
    right=<Tunnel2_AWS_Outside_IP>
    type=tunnel
    ikelifetime=8h
    keylife=1h
    phase2alg=aes128-sha1-modp1024
    ike=aes128-sha1-modp1024
    leftsubnet=192.168.1.0/24
    rightsubnet=10.0.0.0/16
    dpddelay=10
    dpdtimeout=30
    dpdaction=restart
```

Start StrongSwan:
```bash
sudo systemctl start strongswan
sudo systemctl enable strongswan
sudo strongswan statusall
```

✅ You should see both tunnels attempting to establish. This may take 1–2 minutes.

### Update route table in TrainingVPC
Add a route so TrainingVPC knows to send on-prem traffic through the VGW:

1. Go to **VPC → Route Tables → PublicRT → Routes → Edit routes → Add route**:
   - **Destination:** `192.168.1.0/24`
   - **Target:** Virtual Private Gateway → `TrainingVGW`

## Step 7 – Monitor Tunnel State in CloudWatch

1. Go to **CloudWatch → Metrics → All metrics → VPN → By VPN Connection ID**.
2. Find your VPN connection ID and select the **TunnelState** metric.
   - `1` = tunnel is UP
   - `0` = tunnel is DOWN
3. Click **Graphed metrics** — you should see both tunnels with a value of `1`.

### Create a CloudWatch Alarm
4. Go to **CloudWatch → Alarms → Create Alarm → Select metric**.
5. Navigate to **VPN → By VPN Connection ID → TunnelState**.
6. Select one tunnel → **Select metric**.
7. Configure:
   - **Statistic:** Minimum
   - **Period:** 1 minute
   - **Threshold:** Less than 1
   - **Datapoints to alarm:** 1 out of 1
8. Under **Notification**:
   - Create a new SNS topic named `VPNAlerts`
   - Enter your email address
   - Click **Create topic**
9. Confirm the subscription email AWS sends you.
10. Click **Create alarm**.

---

## Step 8 – Simulate Tunnel Failover

To simulate a tunnel going down, stop StrongSwan for Tunnel 1 only from OnPremServer:

```bash
# Bring down only Tunnel 1
sudo strongswan down Tunnel1
```

Then observe in AWS:

1. Go to **VPC → Site-to-Site VPN Connections → TrainingVPN → Tunnel details**.
2. One tunnel should show **Status: DOWN**, the other remains **UP**.
3. Go to **CloudWatch → Alarms** — the alarm should trigger within 1–2 minutes.
4. Check your email — you should receive the SNS alert.

### Restore Tunnel 1
```bash
sudo strongswan up Tunnel1
sudo strongswan statusall
```

Both tunnels should return to UP state and the alarm should resolve.

## Verification Checklist

| Test | Expected Result |
|------|-----------------|
| VPN connection status | Available |
| Both tunnels initial state | Status: UP (TunnelState = 1) |
| CloudWatch TunnelState metric | Value = 1 for both tunnels |

| CloudWatch alarm | Triggers within 1–2 minutes |
| SNS email received | VPN tunnel state alert delivered |
| After `strongswan up Tunnel1` | Both tunnels return to UP |
| Alarm state | Returns to OK |

## Key Takeaways

| Concept | Description |
|---------|-------------|
| Virtual Private Gateway | AWS-side VPN endpoint — attached to a VPC |
| Customer Gateway | Represents the on-premises VPN device in AWS |
| Two tunnels | AWS always creates two for redundancy — one active, one standby |
| TunnelState metric | CloudWatch metric: 1 = UP, 0 = DOWN |
| StrongSwan | Open-source IPsec VPN software — simulates on-prem device in lab |
| SNS + CloudWatch | Alert delivery pipeline for tunnel state changes |
