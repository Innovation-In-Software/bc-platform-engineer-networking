# Lab 02 – Building a Load-Balanced Web Tier

**Objective:**  
Create a scalable and fault-tolerant web architecture using **Application Load Balancer (ALB)**.  
You'll deploy a second web server across a second Availability Zone and test load balancing and failover behaviour.

---

## Topology

```
               ┌─────────────┐
Internet ⇄ ALB │  HTTP:80    │
               └─────────────┘
               /             \
   WebServer (AZ1)       WebServer2 (AZ2)
   PublicSubnetA          PublicSubnetB
   10.0.1.0/24            10.0.20.0/24
```

---

## Before You Start — Confirm Existing Resources

This lab continues from the previous module. Confirm the following are in place before proceeding:

| Resource | Name | Expected State |
|----------|------|----------------|
| VPC | TrainingVPC | Available |
| Public Subnet | PublicSubnetA | 10.0.1.0/24 — AZ us-east-1a |
| Private Subnet | PrivateSubnetB | 10.0.2.0/24 — AZ us-east-1b |
| EC2 Instance | WebServer | Running in PublicSubnetA |
| Security Group | WebServerSG | Attached to WebServer — allows HTTP 80 and SSH 22 |

---

## Step 1 – Create a Second Public Subnet

Your VPC already has `PublicSubnetA (10.0.1.0/24)` and `PrivateSubnetB (10.0.2.0/24)`. You need a **second public subnet** in a different AZ for the ALB to span two zones.

> **Important:** Do not use `10.0.2.0/24` — it is already taken by PrivateSubnetB. Use `10.0.20.0/24` instead.

1. Go to **VPC → Subnets → Create Subnet**.
2. Configure:
   - **VPC:** `TrainingVPC`
   - **Subnet name:** `PublicSubnetB`
   - **Availability Zone:** `us-east-1b`
   - **IPv4 CIDR block:** `10.0.20.0/24`
3. Click **Create subnet**.
4. Select **PublicSubnetB** → **Actions → Edit subnet settings** → check **Enable auto-assign public IPv4 address** → **Save**.

✅ You now have two public subnets in different AZs — required for an internet-facing ALB.

---

## Step 2 – Install Apache on the Existing WebServer

The existing WebServer needs a web page running before it can be added to the load balancer.

SSH into WebServer and run:
```bash
sudo yum install -y httpd
echo "Hello from $(hostname)" | sudo tee /var/www/html/index.html
sudo systemctl start httpd
sudo systemctl enable httpd
```

Verify it is working:
```bash
curl http://localhost
```
✅ Expected: `Hello from ip-10-0-1-xx`

---

## Step 3 – Launch WebServer2 in PublicSubnetB

1. Go to **EC2 → Launch Instance**.
2. Configure:
   - **Name:** `WebServer2`
   - **AMI:** Amazon Linux 2023
   - **Instance type:** t2.micro
   - **Key pair:** same key as WebServer
3. Under **Network settings → Edit**:
   - **VPC:** `TrainingVPC`
   - **Subnet:** `PublicSubnetB`
   - **Auto-assign public IP:** Enable
4. Under **Security Group**: select **existing** → choose `WebServerSG`

   > **Why reuse WebServerSG?** Both web servers need the same rules — HTTP (80) open to the ALB and SSH (22) for access. Creating a new SG with identical rules is unnecessary.

5. Under **Advanced details → User data**, paste:
```bash
#!/bin/bash
sudo yum install -y httpd
echo "Hello from $(hostname)" | sudo tee /var/www/html/index.html
sudo systemctl start httpd
sudo systemctl enable httpd
```

6. Click **Launch instance**.

### Verify WebServer2 is serving traffic
Once the instance is running, SSH in and check:
```bash
curl http://localhost
```
✅ Expected: `Hello from ip-10-0-20-xx`

---

## Step 4 – Create a Target Group

The target group defines which instances the ALB sends traffic to and monitors their health.

1. Go to **EC2 → Target Groups → Create Target Group**.
2. Configure:
   - **Target type:** Instances
   - **Name:** `WebTG`
   - **Protocol:** HTTP
   - **Port:** 80
   - **VPC:** `TrainingVPC`
   - **Health check path:** `/`
3. Click **Next**.
4. On the **Register targets** page, select **both WebServer and WebServer2** → click **Include as pending below**.
5. Click **Create target group**.

> **Which two instances?** `WebServer` (in PublicSubnetA) and `WebServer2` (in PublicSubnetB). Do not add DBServer.

### Wait for targets to become healthy
Go to **Target Groups → WebTG → Targets** tab. Wait until both instances show:
```
Health status: Healthy
```
> If targets stay **unhealthy**, SSH into each instance and run `curl http://localhost` to confirm httpd is running. If it is not, run the install commands from Steps 2 and 3.

---

## Step 5 – Create the Application Load Balancer

1. Go to **EC2 → Load Balancers → Create Load Balancer → Application Load Balancer**.
2. Configure:
   - **Name:** `TrainingALB`
   - **Scheme:** Internet-facing
   - **IP address type:** IPv4
3. Under **Network mapping**:
   - **VPC:** `TrainingVPC`
   - **Mappings:** check both AZs — select `PublicSubnetA` for us-east-1a and `PublicSubnetB` for us-east-1b
4. Under **Security Groups**: select `WebServerSG` (allows HTTP 80 from anywhere).
5. Under **Listeners and routing**:
   - **Protocol:** HTTP
   - **Port:** 80
   - **Default action:** Forward to → `WebTG`
6. Click **Create load balancer**.

✅ The ALB will be provisioned in a few minutes. Copy the **DNS name** shown (e.g. `trainingalb-xxxx.us-east-1.elb.amazonaws.com`) — you will need it for testing.

---

## Step 6 – Test Load Balancing

Open your browser and navigate to:
```
http://trainingalb-xxxx.us-east-1.elb.amazonaws.com
```

> **Use HTTP not HTTPS** — the ALB only has an HTTP:80 listener. If you type `https://` the browser will time out.

Refresh the page several times. You should see responses alternate between:
- `Hello from ip-10-0-1-xx` (WebServer in PublicSubnetA)
- `Hello from ip-10-0-20-xx` (WebServer2 in PublicSubnetB)

✅ The ALB is distributing traffic across both instances.

---

## Step 7 – Simulate Failover

1. Go to **EC2 → Instances** → select **WebServer2** → **Instance State → Stop**.
2. Wait about 30 seconds for the ALB health check to detect the failure.
3. Refresh your browser — all responses should now come from **WebServer** only.
4. Restart WebServer2 and confirm both servers return to healthy status in the target group.

✅ The ALB automatically removed the unhealthy instance from rotation with no downtime.

---

## Verification Checklist

| Test | Expected Result |
|------|-----------------|
| `curl http://localhost` on WebServer | Returns "Hello from ip-10-0-1-xx" |
| `curl http://localhost` on WebServer2 | Returns "Hello from ip-10-0-20-xx" |
| Both targets in WebTG | Health status: Healthy |
| ALB DNS in browser | Alternates between both servers on refresh |
| After stopping WebServer2 | All traffic goes to WebServer — no error |
| After restarting WebServer2 | Both servers return to healthy rotation |
